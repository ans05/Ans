# SoundRoute — Architecture (Phase 1 proposal)

## 1. Guiding principles

1. **Local first.** `docker compose up` must give a complete working product. AWS is a deployment target, not a dependency.
2. **Three kinds of data, never blended.** Every telemetry row is one of:
   - *Application telemetry* — what the player/API observed (browser timings, API request durations, listener actions).
   - *AWS network telemetry* — what AWS observed (VPC Flow Logs, CloudFront logs).
   - *Simulated* — generated by `scripts/simulate.py`. Every telemetry table has `data_source IN ('real','simulated')` and the UI has a toggle/badge.
3. **No fabricated measurements.** If something can't be measured (see §6), the UI says so.
4. **Observational, not causal.** Dashboards show correlations with sample sizes; copy never says "latency causes skips".

## 2. Production architecture

```
                         ┌────────────────────────── AWS region ───────────────────────────┐
                         │                                                                  │
 Listener (browser)      │   CloudFront (HTTPS, global edge cache)                          │
   │                     │     ├─ /            → S3 bucket "web"    (React build)  [OAC]    │
   │  HTTPS              │     ├─ /audio/*     → S3 bucket "audio"  (cached, long TTL) [OAC]│
   └────────────────────►│     └─ /api/*       → ALB origin         (no cache)              │
                         │                            │                                     │
                         │  ┌──────────── VPC 10.0.0.0/16 ──────────────────────────────┐   │
                         │  │ Public subnets  (AZ-a, AZ-b)      : ALB, NAT gateway       │   │
                         │  │ Private-app     (AZ-a, AZ-b)      : EC2 ASG (FastAPI)      │   │
                         │  │ Private-data    (AZ-a, AZ-b)      : RDS PostgreSQL         │   │
                         │  └────────────────────────────────────────────────────────────┘   │
                         │  VPC Flow Logs ─► S3 / CloudWatch Logs ─► ingest job ─► Postgres  │
                         │  CloudFront logs ─► S3 ─► ingest job ─► Postgres (cache hit ratio)│
                         └──────────────────────────────────────────────────────────────────┘
```

Request paths:

| Path | Route |
|---|---|
| Static site | Browser → CloudFront → S3 (web) |
| Audio | Browser → CloudFront → (cache hit: served at edge) / (miss: S3 audio) |
| API + telemetry | Browser → CloudFront `/api/*` → ALB → EC2 (FastAPI) → RDS |
| Secrets | EC2 → SSM Parameter Store (via instance role) |

### Deliberate deviation from the brief
You described `Listener → ALB` for API calls. I propose routing `/api/*` **through CloudFront** to the ALB instead:
- Without a domain name we have no ACM certificate for the ALB, so the ALB can only speak HTTP. An HTTPS page calling an HTTP API is blocked by browsers (*mixed content*). CloudFront provides HTTPS on its default `*.cloudfront.net` domain for free.
- One origin for site + API = no CORS in production.
- The ALB security group can be restricted to CloudFront's managed prefix list, so the ALB isn't directly reachable from the internet.
- Trade-off: CloudFront→ALB hop is HTTP (inside AWS's network, but unencrypted). Documented as a known limitation; fix = custom domain + ACM cert on ALB.

## 3. Local architecture (Docker Compose)

```
browser :5173 ──► frontend (Vite dev server)
browser :8000 ──► backend (FastAPI/uvicorn) ──► db (postgres:16)
                    └─ /media/* static files from ./media (stand-in for CloudFront+S3)
```
Services: `db`, `migrate` (runs Alembic, exits), `backend`, `frontend`, `seed` (one-shot: tracks, artists, demo users). Simulation is run on demand: `docker compose run --rm backend python scripts/simulate.py ...`.

Local media is served by FastAPI `StaticFiles`; the DB stores an **`audio_key`** (e.g. `audio/aurora-drift.mp3`), and the API composes the URL from `MEDIA_BASE_URL`. Same data works locally (`localhost`) and in AWS (CloudFront domain).

## 4. Networking concepts and why they appear here

| Concept | Where | Why |
|---|---|---|
| **VPC** | one VPC, `10.0.0.0/16` | A private, isolated network *you* define inside AWS. Nothing in it is reachable unless you route/allow it. |
| **Subnets** | 3 tiers × 2 AZs | A subnet is a slice of the VPC's IP range living in one AZ. *Public* = route table has a route to an Internet Gateway. *Private* = no such route. Tiering lets us apply different routing/rules per role. |
| **Routing** | route tables | Each subnet's route table decides where packets for a destination CIDR go: `local` (inside VPC), IGW (internet), NAT (outbound-only internet). |
| **NAT gateway** | public subnet | Private instances need *outbound* internet (OS updates, pulling images) but must not accept *inbound* internet connections. NAT rewrites their source IP to its own public IP and tracks connections. **Costs money (~$30+/mo idle)** → controlled by `enable_nat` variable; alternative is VPC endpoints. |
| **Security groups** | per tier | Stateful per-ENI firewalls. Chain: `ALB-SG` allows 443/80 from CloudFront; `App-SG` allows 8000 *only from ALB-SG*; `DB-SG` allows 5432 *only from App-SG*. Referencing SGs (not CIDRs) means rules follow instances as they scale. |
| **Load balancing** | ALB, health checks on `/healthz` | Spreads HTTP requests across instances in multiple AZs and removes unhealthy ones. Layer 7 (it understands HTTP), unlike an NLB (layer 4). |
| **Auto Scaling** | ASG min 1 / desired 1 / max 2 | Replaces failed instances and adds capacity on load. Kept at 1–2 for cost; the point is demonstrating the mechanism. |
| **CDN caching** | CloudFront + S3 | Audio files are immutable, so cache them at edge locations near users. A *hit* skips the trip to S3 — lower latency, less origin load. We read the `X-Cache` header to measure hit/miss. |
| **DNS** | `*.cloudfront.net`, ALB DNS name | Names resolve to many IPs (edge locations/AZs). Browser DNS time is visible in Resource Timing. Custom domain/Route 53 is an optional future step (cost + registration). |
| **HTTP/HTTPS, TCP, ports** | 443 edge, 80/8000 internal, 5432 DB | HTTPS = HTTP over TLS over TCP. Ports identify services; flow logs show them. |
| **VPC Flow Logs** | on the VPC | Records metadata (src/dst IP, ports, protocol, bytes, packets, ACCEPT/REJECT) per flow per ~1–10 min window for ENIs *inside* the VPC. No payloads, no latency. |
| **Latency vs throughput** | analytics | Latency = time for one round trip/first byte; throughput = bytes per second. Streaming is sensitive to both in different ways (start delay vs rebuffering). We measure them separately. |

Each of these gets a short "concept" box in the README and in the Terraform file that creates it.

## 6. What is and isn't measurable (honesty table)

| Signal | Source | Real? | Limits |
|---|---|---|---|
| Time-to-first-audio, buffering count/duration, skips, completes | Browser `<audio>` events | ✅ app telemetry | Includes decode/render time, not pure network |
| API round-trip ("client RTT") | Browser `fetch('/api/ping')` timed | ✅ app telemetry | Includes TLS, server time, queueing. **Not** ICMP latency. Called `client_rtt_ms`, never "network latency" |
| DNS/connect/TTFB/transfer for audio | `PerformanceResourceTiming` | ✅ app telemetry | Cross-origin detail requires `Timing-Allow-Origin`; I'll set it via CloudFront response headers policy (same-origin locally) |
| Cache hit/miss per stream | `X-Cache` response header (exposed via CloudFront headers policy) | ✅ AWS-derived | Only on CloudFront; local = `NA` |
| Cache hit ratio overall | CloudFront standard logs | ✅ AWS | Delivered with minutes of delay |
| Bytes/packets/ports/ACCEPT/REJECT | VPC Flow Logs | ✅ AWS | Only ENI traffic inside the VPC (ALB↔EC2, EC2↔RDS, NAT, internet scans hitting ALB). **Cannot see CloudFront→user traffic. No latency. No session ID. Aggregated windows.** |
| Per-session link between flow logs and a listener | — | ❌ not possible | Flow logs have IPs only; we won't claim per-user joins |
| API server latency | FastAPI middleware | ✅ app telemetry | Server-side processing time only |
| Everything from `simulate.py` | script | ⚠️ simulated | Tagged `data_source='simulated'` |

Consequence: the original single `network_metrics` table is split into three, because one table with "session id + latency + ports + packets" would mix incompatible sources (see schema doc).

## 7. Security approach (summary)
- Only ALB (and NAT) in public subnets; EC2 and RDS private. RDS `publicly_accessible = false`, SG allows 5432 from App-SG only.
- S3 buckets private, Block Public Access on; CloudFront reads via Origin Access Control.
- EC2 uses an IAM instance profile scoped to: read SSM params under `/soundroute/*`, ship logs/metrics. No SSH (use SSM Session Manager).
- DB password generated by Terraform (`random_password`) and stored in Secrets Manager/SSM SecureString — not in git; note that it also lands in Terraform state, so state must be treated as sensitive (remote encrypted state recommended).
- RDS storage encryption on; flow log bucket encrypted.
- Telemetry endpoint: payload size limits, enum validation, rate limiting per IP (simple), idempotency keys. No PII: users are demo usernames.

## 8. Cost stance
Cost-bearing resources: NAT gateway, ALB, RDS, EC2, CloudFront/S3 data transfer, CloudWatch Logs ingestion, Flow Logs. Mitigations: `db.t4g.micro` single-AZ, `t4g.micro` instances, one NAT (toggle), Flow Logs → S3 with lifecycle expiry, 1–7 day log retention, budget alarm in Terraform, `terraform destroy` + checklist in docs. Exact figures will be stated in Phase 4 from current AWS pricing, not guessed now.

## 9. Key decisions (ADR-lite)

| # | Decision | Why | Alternative rejected |
|---|---|---|---|
| 1 | Project in `soundroute/` subfolder | Repo already holds an unrelated Chrome extension | Overwriting it |
| 2 | Events append-only + derived `streams` table | Raw events are truth; one row per play attempt makes engagement SQL simple and fast | Reconstructing streams with window functions on every query |
| 3 | Split network data into 3 tables | Different grain & source; honest | One wide `network_metrics` |
| 4 | `audio_key` not `audio_url` in DB | Same data local & AWS | Hard-coded URLs |
| 5 | CloudFront in front of ALB for `/api/*` | HTTPS without a domain, no CORS | Raw ALB (mixed content) |
| 6 | Alembic migrations, SQLAlchemy 2.0 sync + psycopg3 | Simple, well-understood; async adds complexity with no benefit at this scale | async SQLAlchemy |
| 7 | Detectors as a `Detector` protocol | Isolation Forest later = new class, no pipeline change | Hard-wired z-score |
| 8 | Flow Logs → S3 (primary), CloudWatch for metrics/alarms | Logs ingestion to CloudWatch Logs is pricier; S3 is cheap and batch-friendly | Everything in CloudWatch Logs |
| 9 | Demo audio is synthesised originals | Legally clean, reproducible | Downloading music |
| 10 | No user auth (demo usernames) | Out of scope; avoids fake security theatre. Documented limitation | Half-built auth |
